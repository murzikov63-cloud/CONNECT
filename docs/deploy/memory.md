# Расчёт памяти на 2 ГБ

Для 4 номеров WhatsApp:

| Часть | Ожидаемо | Потолок |
|---|---|---|
| Postgres | ~200 МБ | 512 МБ |
| Redis (очередь) | ~40 МБ | 128 МБ |
| Сервис (4 сессии) | ~250 МБ | 768 МБ |
| Caddy | ~25 МБ | 96 МБ |
| Система | ~150 МБ | — |
| **Итого в работе** | **~670 МБ** | из 2000 МБ |

Сумма потолков (1504 МБ) намеренно меньше 2 ГБ: остаётся запас системе,
чтобы при упоре в лимиты сервер оставался управляемым.

## Настройки Postgres

По умолчанию Postgres рассчитан на машину побольше и в тесноте начинает
свопиться. Поэтому заданы явно: `shared_buffers=128MB`,
`effective_cache_size=384MB`, `work_mem=4MB`, `max_connections=40`.

## Почему очередь не выбрасывает задания

У Redis выставлено `maxmemory-policy noeviction`. При заполнении он вернёт
ошибку, а не выкинет старые записи — сообщение окажется в «не отправлено»
с алертом, а не пропадёт молча. Ради этого и стоит порог оповещения в 80%.

## Когда увеличивать сервер

Сигнал — не разовый скачок, а **постоянно занятая подкачка** (сторож пришлёт
отдельное предупреждение). DigitalOcean увеличивает память и процессор
без переустановки: выключение, resize, включение — около двух минут.
