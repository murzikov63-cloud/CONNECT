# Создание сервера под Messenger

## Настройки при создании (DigitalOcean)

| Поле | Значение |
|---|---|
| **Region** | Frankfurt — **FRA1** |
| **Image** | Ubuntu **24.04 (LTS) x64** |
| **Droplet Type** | Basic |
| **CPU options** | **Premium AMD** или **Premium Intel** (NVMe) |
| **Размер** | **2 GB RAM / 1 vCPU / 50 GB NVMe** — это ~$14/мес |
| **Authentication** | **SSH Key** (не пароль), ключ ниже |
| **Hostname** | `messenger-connect-fra1` |
| **Monitoring** | включить (бесплатно) |
| **Backups** | по желанию, +20% к цене; у нас есть свои ежедневные дампы |
| **VPC / Tags** | по умолчанию |

Про выбор диска: обычный вариант за $12 даёт SSD, Premium за $14 — NVMe.
Разница в цене $2, а диск для базы данных — самое узкое место. Берём Premium.

## Ключ доступа

Вставить в поле SSH Key при создании (New SSH Key → Paste):

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAINfPiOI/lBr1hum9OLW2k3XhfSiqzdSVbqF+N7iiO5Bu messenger-connect deploy
```

Приватная часть лежит на TONYAI в `~/.ssh/messenger-connect` и никуда не уходит.
Пароль для входа не нужен и не создаётся — это сразу закрывает самый частый
способ угона сервера.

## После создания

Прислать IP. Дальше всё делается скриптом, вмешательство не требуется.

## Защита от нехватки памяти

2 ГБ хватает с запасом (расчёт — в `docs/deploy/memory.md`), но защита
ставится всё равно, потому что «хватает по расчёту» и «хватает всегда» —
разные вещи.

Три уровня:

1. **Потолки для каждой части.** Ни один контейнер не может съесть всю память:
   база 512 МБ, очередь 128 МБ, сервис 768 МБ, веб-сервер 96 МБ.
   Прописано в `docker-compose.yml`.
2. **Порядок жертв.** Если памяти всё-таки не хватит, система убьёт **сервис**,
   а не базу и не очередь: сервис поднимется сам за секунды и переподключится,
   а вот повреждённая база — это восстановление из бэкапа.
3. **Файл подкачки 2 ГБ.** Разовый всплеск переживается с замедлением,
   а не с падением.

Плюс сторож (`deploy/resource-watch.sh`, таймер каждые 5 минут) шлёт в Telegram
предупреждение при памяти или диске выше 80%, при заполнении подкачки больше
половины и при пропаже любого контейнера. Одна и та же жалоба — не чаще
раза в час.

Сторож намеренно сделан обычным скриптом по таймеру, а не через модель:
механические проверки должны работать и тогда, когда всё остальное лежит.

## Файл подкачки (делается при установке)

    fallocate -l 2G /swapfile
    chmod 600 /swapfile
    mkswap /swapfile
    swapon /swapfile
    echo '/swapfile none swap sw 0 0' >> /etc/fstab
    # Свопить только при реальной нужде, а не «на всякий случай»
    sysctl -w vm.swappiness=10
    echo 'vm.swappiness=10' > /etc/sysctl.d/99-swappiness.conf
