# connect.indolight.com — DNS, сертификат, скорость

**Решение принято 2026-08-18: проксирование через Cloudflare оставляем.**
Не переделывать без причины — ниже разобраны плюсы и минусы, вопрос закрыт.

Сервер: Франкфурт. Запись типа `A` на его IP, **проксирование включено
(оранжевое облако)**.

## Почему так

- Адрес сервера скрыт, случайные сканеры до него не доберутся.
- Сертификат Cloudflare Origin живёт 15 лет — убираем типовую причину
  падения сервиса «забыли продлить сертификат».
- Единообразно с остальными сервисами (n8n, board, parser).

Минус, который принят осознанно: Cloudflare расшифровывает трафик у себя,
то есть переписка с клиентами и их файлы проходят через него в открытом виде.

## Два обязательных условия

1. **Cloudflare Access на этот адрес вешать нельзя.** Он требует логин,
   amoCRM логиниться не умеет — вебхуки молча отвалятся. На n8n и board
   Access стоит правильно, здесь он всё сломает.
2. **Сервер закрыть файрволом так, чтобы пускало только сети Cloudflare.**
   Иначе адрес найдут сканированием и скрытие теряет смысл.
   Актуальные сети: https://www.cloudflare.com/ips/

## Сертификат

Режим шифрования в панели Cloudflare: **Full (strict)**.
SSL/TLS → Origin Server → Create Certificate, оба файла положить
в `caddy/origin/` как `cert.pem` и `key.pem` (приватный ключ показывают
только один раз при создании).

## Скорость

Ожидаемая надбавка от лишнего звена — десятки миллисекунд: Cloudflare держит
с сервером постоянное соединение и не пересоздаёт его на каждый запрос.
На фоне бюджета в 5 секунд из раздела 8 ТЗ это доли процента.

**Замерить на месте при установке** и записать сюда фактические числа:

    # время полного ответа нашего health-эндпоинта
    curl -s -o /dev/null -w 'всего: %{time_total}s, TLS: %{time_appconnect}s\n' \
      https://connect.indolight.com/api/health

Если разница окажется больше 300 мс — вернуться к вопросу проксирования.

## Проверка после поднятия

    curl -I https://connect.indolight.com/api/health
