# Шаг 3. Промпт для Lovable

Откройте Lovable, создайте новый проект и вставьте текст ниже целиком.
Занимает около 10 минут, дальше Lovable соберёт интерфейс сам.

Когда приложение будет готово — **пришлите мне его адрес** (что-то вида
`https://ваш-проект.lovable.app`). Мне нужно разрешить ему обращаться
к серверу, без этого браузер заблокирует запросы.

---

Собери админку для сервиса Messenger — моста между WhatsApp и amoCRM.
Весь интерфейс на русском языке.

**Бэкенд уже готов.** Его спецификация лежит по адресу
`https://connect.indolight.com/api/openapi.json` — прочитай её и построй
клиент по ней, не выдумывай эндпоинты.

Базовый адрес API: `https://connect.indolight.com`

## Авторизация

- Экран входа: одно поле «Пароль» и кнопка «Войти».
- Отправляй `POST /api/auth/login` с телом `{ "password": "..." }`.
- В ответ приходит `{ token, expiresAt }`. Сохрани токен в localStorage.
- Все остальные запросы шли с заголовком `Authorization: Bearer <token>`.
- Если сервер ответил 401 — стирай токен и возвращай на экран входа.
- Если 429 — покажи «Слишком много попыток, подождите 15 минут».

## Экран 1. Дашборд

Данные из `GET /api/health`. Четыре плитки:

- **Номера**: «сколько в сети из скольких». Зелёная, если все в сети;
  красная, если есть номера в состоянии `banned` или `logged_out`.
- **Сообщений за сутки**.
- **Не отправлено**: число. Красная, если больше нуля, и кликабельная —
  ведёт в журнал с фильтром «не отправлено».
- **Связь с amoCRM**: «подключена» или «не подключена» по полю
  `chatApiConnected`.

Обновляй раз в 15 секунд.

## Экран 2. Номера

Список карточек из `GET /api/numbers`. В каждой:

- Название и телефон (если номер уже подключён).
- Статус цветной меткой. Переводи так:
  `online` → «В сети» (зелёный), `offline` → «Нет связи» (жёлтый),
  `qr` → «Ждёт сканирования» (синий), `connecting` → «Подключается» (серый),
  `banned` → «Заблокирован WhatsApp» (красный),
  `logged_out` → «Отвязан, нужен новый QR» (красный),
  `new` → «Новый» (серый).
- Сколько времени в сети (`uptimeSec`, показывай как «3 ч 12 мин»).
- За сутки: входящих, исходящих, не отправлено.
- Кнопки: «Подключить» (только если статус не `online`), «Перезапустить»,
  «Удалить» (с подтверждением, текст: «Номер будет отвязан от WhatsApp.
  Переписка сохранится. Продолжить?»).

Сверху кнопка «Добавить номер» — спрашивает название
(например «Отдел продаж 1») и шлёт `POST /api/numbers` с `{ label }`.
После создания сразу открывай окно подключения.

## Экран 3. Подключение номера (окно поверх)

Это главный экран, сделай его понятным.

- Заголовок: «Подключение номера».
- Инструкция в три шага: 1) Откройте WhatsApp на телефоне.
  2) Настройки → Связанные устройства → Привязка устройства.
  3) Наведите камеру на этот код.
- Картинка QR: запрашивай `GET /api/numbers/{id}/qr` **каждые 2 секунды**.
  Ответ `{ qr }` — это data-url, вставляется прямо в `<img src={qr}>`.
- Если пришёл 404 — покажи «Готовим код…» и продолжай опрашивать.
- Параллельно опрашивай `GET /api/numbers`. Как только у этого номера
  статус стал `online` — закрой окно и покажи «Номер подключён».
- Предупреждение внизу мелким шрифтом: «Код обновляется каждые 20 секунд,
  это нормально».

## Экран 4. Журнал сообщений

Таблица из `GET /api/messages`. Колонки: время (`occurred_at`), номер
(`number_label`), контакт (`chat_name`, под ним `chat_phone`),
направление (стрелка внутрь или наружу), тип, текст (`preview`;
для вложений покажи `media_name`), статус.

Статусы переводи: `received` → «Получено», `queued` → «В очереди»,
`sent` → «Отправлено», `delivered` → «Доставлено», `read` → «Прочитано»,
`failed` → «Не отправлено» (красным, и покажи `error` подсказкой).

Фильтры сверху: по номеру (выпадающий список), по статусу, по направлению,
и поле поиска по телефону или имени (параметр `q`).

У строк со статусом `failed` — кнопка «Повторить»:
`POST /api/messages/{id}/retry`, потом обнови таблицу.

Постраничность через `limit` и `offset`, по 50 строк.

## Экран 5. Настройки

Форма из `GET /api/settings`, сохранение через `PUT /api/settings`
(можно отправлять только изменённые поля).

- **Личные номера** (`personalNumbers`) — список строк, можно добавлять
  и удалять. Подпись: «Переписку с этими номерами не передавать в amoCRM».
- **Игнорировать групповые чаты** (`ignoreGroups`) — переключатель.
- **Лимит новых чатов на номер в сутки** (`newChatsPerNumberPerDay`) — число.
  Подпись: «Защита от блокировки номера. Ноль — без ограничений».
- **Пауза перед первым сообщением новому контакту** — два поля
  `newChatDelayMinMs` и `newChatDelayMaxMs`, показывай в секундах,
  а отправляй в миллисекундах.
- **Пауза перед ответом в диалоге** — `replyDelayMinMs` и `replyDelayMaxMs`,
  так же в секундах. Подпись: «Не больше 5 секунд, иначе клиент заметит
  задержку».
- **Воронка и этап для новых сделок** — `amoPipelineId` и `amoStatusId`,
  числовые поля, можно оставить пустыми (тогда «Неразобранное»).

## Оформление

Светлая и тёмная темы. Боковое меню: Дашборд, Номера, Журнал, Настройки.
Просто и без украшательств — этим будут пользоваться каждый день.
Никаких выдуманных данных и заглушек: если API не ответил, показывай ошибку.
